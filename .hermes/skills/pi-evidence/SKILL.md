# PI Evidence Workflow

Every extracted problem must be grounded in source material.

Separate:
1. screening,
2. structured extraction,
3. evidence validation,
4. recurrence/clustering,
5. opportunity synthesis.

For each supported problem retain enough provenance to return to the original
source item.

Evidence must distinguish:
- what the source explicitly says,
- what the system extracted,
- what is inferred,
- what remains unknown.

Never create missing evidence to make an opportunity look stronger.

Use evidence maturity carefully:
SINGLE_SIGNAL -> EMERGING -> RECURRING -> MULTI_SOURCE -> CROSS_MARKET.

Do not upgrade maturity merely because multiple generated summaries use similar wording.

Capture counter-evidence:
- existing satisfactory solution,
- low severity,
- rare edge case,
- no purchasing authority,
- unwillingness to switch,
- workflow not transferable,
- evidence contradiction.

Unknown is a valid result.

Opportunity output should explain why something deserves further investigation,
not claim that a business should be built.
